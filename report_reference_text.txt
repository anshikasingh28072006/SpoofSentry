ABSTRACT
Money Mate is a simple and friendly personal finance tracker that runs completely inside a
web browser. It is built with HTML, CSS and JavaScript, and it uses the Chart.js library to
draw its charts. The project is meant for students and young earners who want to know where
their money goes, without installing a heavy application or creating an online account.
A person may already use a notebook or a spreadsheet for this purpose, but these methods need
manual calculation and do not give an instant picture of spending. Money Mate removes this
effort. It calculates the balance, income, expenses and budget usage automatically every time
a record is added, edited or deleted.
• The first part of the report explains the background of personal finance management
and the technologies used: HTML, CSS, JavaScript, Chart.js and the browser’s
LocalStorage.
• In the second part, the report describes the design and working of Money Mate: a
dashboard with summary cards and charts, transaction management with search, filter
and sort, monthly and category-wise budgets, due-payment reminders, five colour
themes, multi-currency display and profile settings.

INTRODUCTION
Money is a part of everyday life. Students, working people and families all earn, spend and
save money, but very few people keep a clear record of it. At the end of the month many
of us wonder where all the money has gone, and small expenses such as snacks, online
subscriptions or recharge bills quietly add up to a large amount.
Keeping track of money by hand is boring and easy to forget. Spreadsheets are powerful
but need formulas and regular effort, while many mobile applications are crowded with
advertisements, ask for personal details or require an account before they can be used. A
person who only wants to note down an expense and see a quick summary is left without a
simple option.
Thus, in this mini project we have developed Money Mate, a lightweight personal finance
tracker with the tagline “Your money, made simple.” It lets a user record income and
expenses, set a monthly budget and category limits, keep a list of upcoming bills, and see
everything on a clean dashboard with charts. All information is kept on the user’s own
device in the browser, so no sign-up and no server is needed.
The project is built only with core web technologies (HTML, CSS and JavaScript) and one
charting library. It therefore also serves as a good learning example of how a complete and
useful application can be created without any heavy framework. Through this report we
explain each technology used, the design of the application, the working of every screen
and the important parts of the code.
1 INTRODUCTION TO PERSONAL FINANCE MANAGEMENT
1.1 What is personal finance management?
Personal finance management means planning, recording and controlling the money that
comes into and goes out of a person’s hands. It covers four basic activities: recording
income (pocket money, salary, freelance payments, gifts), recording expenses (food,
transport, shopping, education and so on), planning a budget (how much one is willing to
spend in a month) and remembering future payments such as fees, bills and subscriptions.
Good money habits depend on awareness. When a person can clearly see that a large part
of the month’s spending went to one category, it becomes easy to take a decision and cut

down. This is why even a very simple record of income and expenses is useful. The main
benefits of managing personal finance are:
• Awareness of spending: the user knows exactly where the money is going.
• Better planning: a monthly budget gives a target to stay within.
• No missed payments: reminders for bills help to avoid late fees.
• Savings: when expenses are under control, more money can be saved for future
needs.
1.2 Traditional methods and their limitations
Before digital tools, people used notebooks and diaries to write down their expenses. Later,
spreadsheets became popular, and today there are many mobile applications for expense
tracking. Each of these methods has some limitation:
• Notebooks and diaries: totals have to be calculated by hand, entries are easy to
forget, and there is no chart or summary.
• Spreadsheets: the user must create the formulas, filters and charts personally, and
they are not comfortable to use on a small phone screen.
• Mobile applications: many show advertisements, ask the user to create an account,
store personal data on a company server, or keep useful features behind a payment.
Money Mate is designed to remove these difficulties by giving a simple, ready-to-use
tracker that opens in a browser, needs no account and keeps the data with the user.
1.3 Objectives of the project
The objectives of the Money Mate project are:
• To record income and expenses quickly with a category, description, date and
optional note.
• To show summaries for today, this week, this month and this year on one dashboard.
• To let the user set a monthly budget and category-wise limits, and to warn when the
limit is near or crossed.
• To keep track of due payments and remind the user about overdue and upcoming
bills.
• To keep all data private by saving it only in the user’s own browser.

2 WEB TECHNOLOGIES USED
A web application is a program that runs inside a web browser. The browser reads three
kinds of files: HTML for the structure of the page, CSS for its appearance and JavaScript
for its behaviour. Money Mate uses exactly these three, so it works in any modern browser
on a computer or a phone.
2.1 Core technologies
2.1.1 HTML5
HyperText Markup Language (HTML) describes the content of a web page. In Money Mate
the file index.html contains the sidebar menu, the header with the greeting, five pages
(Dashboard, Transactions, Budget, Due Payments and Settings) written as <section>
elements, and the pop-up forms (modals) for adding a transaction, a due payment, a
category and a budget. Semantic tags such as <aside>, <nav>, <main>, <header> and
<section> are used, and form fields have proper labels and ARIA attributes so that the
page is easier for assistive tools to read.
2.1.2 CSS3
Cascading Style Sheets (CSS) control colours, fonts, spacing and layout. The file
style.css uses CSS custom properties (variables) such as --bg, --accent and --ink
for all colours. The five themes (Matcha, Blossom, Lavender, Sky and Sunshine) are simply
five sets of values for these variables, selected by the data-theme attribute on the <body>
tag. Layout is done with Flexbox and CSS Grid, and three media queries (at 1080 px, 860
px and 520 px) make the application adjust itself to tablets and phones.
2.1.3 JavaScript
JavaScript is the programming language of the web and the backbone of Money Mate. The
file script.js holds the whole application logic: loading and saving data, calculating
totals and budgets, drawing the lists and charts, and reacting to every click and form
submission. The code is written in strict mode ('use strict') and uses no framework,
only the standard features available in the browser.

2.3 Browser storage
Money Mate has no server and no database. Instead it uses the LocalStorage feature of the
browser, which can keep a small amount of text on the user’s device. When the page is
opened again, the string is read back and converted into objects. The data stays after the
page is refreshed or the browser is closed, and it is private to that browser on that device.
The limitation is that clearing the browser data also removes the saved records, and the data
is not shared between different devices.

3.1 Variables and constants
Variables store values. JavaScript has two modern ways to declare them. const creates a
name whose value cannot be reassigned, and let creates a name whose value can change
later. In Money Mate, fixed settings such as the storage key and the list of themes are const,
while the application state S, which changes whenever the user adds or removes a record,
is declared with let.
3.2 Functions and arrow functions
A function is a block of code that performs one job and can be used again and again. Short
functions can be written as arrow functions using the => symbol. The following two lines
are used throughout the project: sum adds the amounts of a list of transactions, and ofType
picks only the income or only the expense records.
3.3 Arrays and array methods
The transactions of the user are stored in an array. JavaScript gives powerful methods to
work with arrays. filter() keeps only the items that satisfy a condition, reduce()
combines all items into a single value (for example a total), map() converts every item into
something else and sort() arranges the items in order. The Transactions page uses all of
them to search, filter and sort the records without any extra library.

3.5 The Document Object Model (DOM)
The DOM is the browser’s tree-like representation of the HTML page. JavaScript can find
any element in this tree and change its text, style or children. Money Mate defines a tiny
helper $ to find an element by its id, and then writes the new values into the page. To show
a list, the code creates new elements with document.createElement() and appends them
to the correct container.
Whenever text typed by the user is placed inside HTML, it is first passed through the small
function esc(), which converts special characters. This prevents a name such as <b> from
being treated as real HTML code.
3.6 Events and event delegation
An event is something that happens on the page, for example a click, a key press or a form
submission. JavaScript listens to events with addEventListener(). Buttons in Money
Mate are created dynamically (for example the edit and delete buttons of every transaction),
so it would be difficult to attach a listener to each of them. Instead the project uses event
delegation: one single listener on the whole document checks which element was clicked
with closest() and then performs the correct action.
3.7 JSON and localStorage
JSON (JavaScript Object Notation) is a text format for storing objects. JSON.stringify()
converts an object into text and JSON.parse() converts the text back into an object.
Together with localStorage.setItem() and localStorage.getItem() they let Money

4.3 Data model
The whole data of the application is kept in one JavaScript object called the state. It is

5.8.1 State and storage
When the page opens, the function loadState() creates a fresh state and then tries to read
the saved data from localStorage. Every saved record is checked: transactions and due
payments without an id or without a valid amount are ignored, and an unknown currency
or theme is replaced by the default one. If the stored text is damaged, the application simply
starts empty instead of crashing. After every change (add, edit, delete, setting) the function
save() writes the state back to the storage and renderAll() redraws every page, so that
all screens always agree with each other.
5.8.2 Currency handling
All amounts are stored in Indian Rupees. The currency selected by the user is used only for
display and for converting what the user types. Fixed rates are kept in a table, and the
function fmt() divides the stored amount by the rate and adds the symbol, while toBase()
converts a typed amount back to rupees. The function toInput() fills an edit form with
the exact stored value so that editing and saving without a change never alters an amount.
Switching from one currency to another and back therefore always gives the same numbers.
Computers store decimal numbers with tiny errors (for example 0.1 + 0.2 is not exactly
0.3). To avoid wrong totals, sums are rounded to four decimal places by the helper r4().
The Japanese Yen is shown without decimals.
5.8.3 Date ranges and budget calculation
The function bounds() returns the first and last day of the selected period. A week always
runs from Monday to Sunday, a month from its first to its last day and a year from 1 January
to 31 December, so that every screen uses the same definition of a period.
The budget status is calculated by one shared function, budgetInfo(). It returns the
percentage used, the width of the progress bar (never more than 100%), the remaining

5.8.4 Charts
The two charts are drawn with Chart.js on <canvas> elements. The bar chart has two bars,
income and expenses, and the doughnut chart has one slice for every expense category of
the selected period. The colours are read from the CSS variables of the active theme, so the
charts change their colours together with the theme. The colours of the doughnut slices are
generated from the hue of the theme’s main colour. Before a chart is created again, the old
one is destroyed to avoid two charts being drawn on top of each other, and the axis labels
use the symbol of the selected currency.
5.8.5 Notifications and user messages
The function renderNotifications() collects reminders every time the data changes:
unpaid payments that are overdue or due within three days, and a message when the
monthly budget is near or crossed. If there is at least one reminder, a dot appears on the bell
icon. Short “toast” messages confirm actions such as “Transaction added” or “Budget
saved”, and a confirmation dialog protects every delete action. Pressing the Escape key
closes any open dialog.

6 CONCLUSION
The purpose of this mini project was to build a simple, useful and private personal finance
tracker with core web technologies. Money Mate fulfils this purpose. A user can record
income and expenses, see instant summaries and charts, plan a monthly and category-wise
budget, keep track of due payments and personalise the application with themes and
currency display, all without creating an account or installing anything.
During the development of this project we learned how a complete application can be made
with HTML, CSS and JavaScript only. We practised important ideas such as keeping all
data in one state object, saving it in the browser with localStorage, redrawing the screen
after each change, handling events with event delegation, working with dates and money
safely, and drawing charts with Chart.js. Designing the five themes with CSS variables and
making the layout responsive also gave us a good understanding of modern interface
design.
The project has some limitations. The data is saved only in one browser on one device, so
it is lost if the browser data is cleared and it cannot be shared between devices. The currency
rates are fixed values used only for display, and an internet connection is needed to load
the chart library, icons and fonts.
In the future, Money Mate can be improved in several ways: exporting the data to a file
such as CSV or PDF, backing up and syncing the data with an online account, recurring
transactions and bills, monthly and yearly trend charts, live currency rates, a dark mode,
and turning the application into an installable app that works fully offline. With such
features Money Mate can grow from a mini project into a complete everyday money
companion.
